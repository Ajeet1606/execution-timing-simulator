Understanding Rate Limiting

A defensive programming technique that restricts the number of times a function or API can be called within a strict, fixed time window to prevent abuse.

How it Works

Time is divided into fixed buckets (e.g., 0:00 to 0:59, 1:00 to 1:59). You are given a strict quota of operations per bucket. As events occur, the quota decreases. If the quota hits zero, the system rejects all further events (dropping them) until the next time bucket begins and the quota is fully refreshed.

🛑 The Nightclub Bouncer Analogy

A popular club has a strict rule: Only 3 VIPs allowed inside every hour. If 5 VIPs show up at 10:15, the first 3 enter. The remaining 2 are rejected and told to return at 11:00 when the quota resets.

Real-World Use Cases

1. Public API Protection

Services like Twitter or GitHub limit clients to 100 API requests per hour. If a developer runs a buggy loop that makes 10,000 requests, the server safely responds with a 429 Too Many Requests error, protecting itself from crashing.

API Quota: 100 req / hour

2. Stopping Brute Force

Hackers use scripts to guess passwords thousands of times a second. Rate limiting a login endpoint to 5 attempts per minute completely neutralizes brute-force dictionary attacks.

Login Attempts: 5 per minute max

3. SaaS Billing Tiers

AI companies offering "Free" vs "Pro" plans use rate limits to enforce fair usage. Free users might be capped at 10 image generations per day, while paying users get an elevated rate limit threshold.

Free Tier: 10 gens / day
